# timelimit-parent: веб-админка родителя для LLM

CLI `timelimit-parent` (короткое имя `tlp`) ходит на сервер синхронизации TimeLimit как ещё одно
родительское устройство семьи. Устройство описано в
`timelimit/docs/parent-console.md`; здесь — как им пользоваться.

## Перед началом

- Токен устройства — секрет. CLI берёт его из `TIMELIMIT_DEVICE_TOKEN` или из `tokenCommand` в
  `~/.config/timelimit-parent/config.json` (команда, печатающая токен из
  зашифрованного хранилища, — голый токен или YAML-строку `parent_device_token: …`). Нет токена — не выдумывай и не проси вставить его в чат: предложи
  человеку выполнить `timelimit-parent login` самому, это интерактивный вход по коду из письма.
- Всегда добавляй `--json`, когда разбираешь вывод: человекочитаемые таблицы — для показа.
- Детей несколько — указывай `--child <имя>` (или имя позиционно у `status`, `usage`, `lock`, `ban list`, `export`).

## Понятия — не путай три разных «дай ещё»

| что просят | команда | что делает |
| --- | --- | --- |
| «+30 минут к игре» | `grant <категория> 30` | доп. время на сегодня; **запрет им не обходится** |
| «ночь, но разреши на 20 минут» | `allow <категория> 20m` или `allow --all 20m` | лимиты и запреты категории/ребёнка выключены до срока |
| «разреши это приложение» | `app move <пакет> <категория>` | перенос приложения в другую категорию |

- **Лимит** — сколько минут в день (`limit set`). Правило действует только в свои дни и часы.
- **Запрет** — интервал «с–до» по дням на набор категорий (`ban add`). Внутри это правила с
  `time=0` на каждой категории; отдельного хранилища нет, Android-приложение видит то же самое.
  Дни — это дни, **когда запрет начинается**: `--days su-th --from 21:00 --to 07:00` — ночи перед учебными днями.
  По умолчанию запрет жёсткий (доп. время его не обходит), `--soft` — обходится доп. временем.
- Приложение без категории заблокировано, если у ребёнка не задана категория по умолчанию.
- `lock` блокирует все корневые категории, включая «Разрешено» (звонилку тоже); снять — `lock --off`.
- 🚨 Лаунчер лежит в категории «Разрешено», и TimeLimit его отдельно не пропускает: **никакой** запрет и
  лимит на эту категорию не ставится — заблокированный лаунчер запирает планшет целиком, включая
  приложения, которым разрешено круглосуточно. Ночь и учёба — только на остальных категориях.
  Фонарик из шторки работает всегда (`com.android.systemui` TimeLimit пропускает сам).

## Сценарий 1. «Сколько сидел и нет ли лазейки»

1. `timelimit-parent status --json` — по категориям: `usedTodayMs`, `limitNowMs`, `remaining`,
   `blockedNow`, `countsTimeNow`; плюс `bans`, `loopholes`.
2. `timelimit-parent usage --days 7 --json` — время по дням и категориям.
3. Разбери лазейки (`loopholes[].kind`):
   - `no-rules` / `no-rule-now` — у категории нет правила, действующего сейчас: **её время не
     записывается вовсе**, поэтому в `usage` лазейка выглядит как ноль. Это главная причина «сидит
     дольше, а статистика чистая». Проверь, какие приложения там (`categories[].apps`).
   - `limits-disabled` — кто-то включил «разрешить до» и забыл.
   - `unassigned-apps-category` — всё неразобранное падает в категорию без действующего лимита.
   - Приложения в «Разрешено» и подкатегориях без правил, чей родитель тоже без правил.
   - `legacyBans` — старые запреты из маски минут; править их только в приложении.
4. Список установленных приложений сервер отдаёт только зашифрованным (`unassignedApps: null`),
   поэтому «что именно установлено» CLI не знает — так и скажи.
5. Отчитайся человеку словами: сколько сидел, где время не считается, что предлагаешь.

## Сценарий 2. Предложить и применить правила

1. Составь предложение словами и покажи `--dry-run` каждой команды:
   ```bash
   timelimit-parent ban add --days su-th --from 21:00 --to 07:00 --all-categories --dry-run --json
   timelimit-parent limit set Игры 60 --days mo-fr --dry-run
   timelimit-parent limit app com.roblox.client 30 --title Roblox --dry-run
   ```
2. **Жди явного согласия человека** на конкретный список действий. Молчание или «ну посмотри» — не согласие.
3. Повтори те же команды без `--dry-run`. Затем `status` — убедись, что правило видно.
4. Ошибка «server rejected at least one of actions» — сервер не говорит, какое именно. Сравни
   вывод `--dry-run` со свежим `status`, не повторяй вслепую.
5. `filter set` требует сервер с `apiLevel` 10; на старом CLI откажет — передай это человеку, не обходи.

Удаление: `ban list` → `ban rm <номер> [--categories ...]`; `limit set <категория> off [--days ...]`.
Устройство из семьи: `device list` → `device remove <id|имя> --dry-run` → после согласия без `--dry-run`;
приложение на нём теряет связь с семьёй, настройки ребёнка остаются. Своё устройство консоли CLI не удаляет.
Настройки самого планшета — `device flags <устройство>` (что включено) и `device flags <устройство>
system-level-blocking=on` (изменить). Главная — `system-level-blocking`: закрытые приложения
замораживаются, пропадает и видео в окошке поверх экрана блокировки. Пароль родителя на планшете не нужен.

## Сценарий 3. Шаблоны, экспорт, импорт

- `template list` — шаблоны с описанием; `template show подросток уроки` — результат наложения.
- Наложение: запреты объединяются, лимиты с одинаковыми днями и окном берут меньший, списки сайтов объединяются.
  Поэтому «каникулы» применяют отдельно и с `--replace`, а не поверх школьного.
- `template apply школьник-младший уроки --dry-run` — по умолчанию `merge`: только добавляет недостающее.
  `--replace` удаляет у затронутых категорий правила, которых нет в шаблоне, — покажи это человеку отдельно.
- Шаблон ссылается на категории по названию («Игры», «Видео», «Соцсети»). Нет такой — будет создана
  пустой с предупреждением: предложи перенести в неё приложения (`app move`), иначе она ничего не ограничивает.
- `export [ребёнок] --out алиса.json` — структура, правила, запреты, приложения, фильтр сайтов; без
  потраченного и доп. времени.
- `import алиса.json --child Боб --dry-run` — на существующего ребёнка как разность (дубли не создаются);
  `import алиса.json --new-child Боб --time-zone Europe/Moscow --dry-run` — новый ребёнок.
- Файл экспорта можно править и применять снова — это и есть способ «настроить через LLM» большим пакетом.

## Чего не делать

- Не применять изменения без `--dry-run` и согласия.
- Не печатать и не сохранять токен; не класть его в `config.json`.
- Не обещать статистику по приложениям и сайтам — её на сервере нет.
